## 1. 서비스 기획

- ✅ **웹 서비스 아이디어 정의**
  - Novel Radar는 한국의 편/회차 단위 웹소설 결제 환경에서, 사용자가 국내외 작품을 결제하기 전에 작품의 특징과 품질을 파악할 수 있도록 돕는 AI 기반 웹소설 분석 서비스이다.
  - 해외 작품은 원어 제목으로 검색할 수 있고, 최종 결과는 한국어로 제공한다.
  - `SERVICE_PLAN.md`에 서비스 개요와 목적을 정리함.

- ✅ **목적 및 타겟 사용자 정의**
  - 목적: 범국가적 웹소설 콘텐츠를 결제 전에 빠르게 파악할 수 있도록 작품 정보, 독자 반응, 장르/분위기 태그, 번역 품질 정보를 제공한다.
  - 타겟: 편/회차 단위로 웹소설을 구매하는 한국인 독자, 특히 해외 웹소설을 직접 외국어 리뷰까지 찾아보기 어려운 사용자.
  - `SERVICE_PLAN.md`에 주요 타겟과 세부 사용자 유형을 정리함.

- ✅ **최소 3개 이상의 페이지/섹션 및 메뉴 이동 설계**
  - `#home` : 서비스 소개/메인 메시지
  - `#about` : 서비스 핵심 가치 설명
  - `#analyze` : 작품 검색 및 AI 분석
  - 상단 메뉴의 `홈 / 소개 / 분석하기` 링크로 각 섹션 이동 가능.

- ✅ **AI 기능 정의**
  - 입력: 웹소설 제목 또는 원제(한국어/영어/중국어/일본어 등)
  - 처리: Gemini + Google Search Grounding으로 작품 식별, 공식 정보, 독자 리뷰, 번역/현지화 근거 조사 후 구조화 분석
  - 출력: 작품 식별 정보, 장르 태그, 분위기/전개 태그, 번역 태그, 스토리 전개, 매력 포인트, 주의 요소, 검색 출처
  - 사용자 가치: 긴 외국어 리뷰를 모두 읽지 않아도 한국어 분석과 태그로 작품의 장르/분위기/번역 품질을 결제 전에 빠르게 파악할 수 있음.

## 4. 반응형 적용 및 확인

- ✅ **반응형 레이아웃 적용**
  - `<meta name="viewport">` 적용.
  - Tailwind 반응형 클래스(`sm:`, `md:`) 사용.
  - 입력창/버튼은 모바일에서 세로(`flex-col`), 넓은 화면에서 가로(`sm:flex-row`).
  - 소개 카드는 모바일에서 1열, 데스크톱에서 3열(`md:grid-cols-3`).
  - 분석 결과는 모바일에서 1열, 데스크톱에서 2열 구성.

- ✅ **최소 2가지 화면 크기 직접 확인**
  - 데스크톱: 확인 완료.
  - 모바일: 실제 휴대폰에서 `https://novel-rader.vercel.app/` 접속 및 동작 확인 완료.
  - 태블릿은 별도 직접 확인 기록은 없으나 동일한 Tailwind 반응형 구조로 대응.

## 5. AI 기능 UX 최소 기준

- ✅ **사용자 입력 UI**
  - 작품명 입력창과 분석 버튼 제공.

- ✅ **AI 결과 화면 출력**
  - 작품 식별 정보, 태그, 스토리 전개, 매력 포인트, 주의/번역 이슈, 검색 출처를 화면에 표시.

- ✅ **실패 처리 안내**
  - 빈 입력: `필수값을 입력하세요` 메시지 표시.
  - API 오류(4xx/5xx): 서버의 `detail` 또는 오류 메시지를 화면에 표시.
  - 지연/타임아웃: 55초 후 요청을 중단하고 `분석 시간이 초과되었습니다` 메시지 표시.
  - AI 구조화 JSON이 중간에 끊기면 백엔드에서 1회 자동 재시도하며, 재실패 시 이해 가능한 분석 실패 메시지를 반환.
  - 최소 요구사항인 1개를 넘어서 여러 실패 유형을 처리하고 있음.

## 6. AI API 연동 (Vercel Serverless Functions - Python)

- ✅ **`api/` Python 엔드포인트 구현**
  - `GET /api/health`
  - `POST /api/analyze`

- ✅ **AI API 호출 및 결과 반환**
  - `google-genai` SDK를 사용해 Gemini API 호출.
  - Google Search Grounding으로 검색 근거를 확보하고, 구조화된 결과를 반환.
  - 근거 부족, API 키 누락, Gemini 호출 실패, 구조화 응답 실패 등을 구분하여 처리.

- ✅ **`requirements.txt` 의존성 정의**
  - `fastapi`
  - `google-genai`
  - `pydantic`

- ✅ **프론트의 `/api/...` 호출**
  - `fetch('/api/analyze', { method: 'POST', ... })`로 백엔드 호출.
  - JSON 응답 검증 및 화면 렌더링 구현.
